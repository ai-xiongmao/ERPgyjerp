# ERPgyjerp 结构优化规划

> 基线：2026-11-11，41 个 Python 文件 / 约 10,440 行 / git 9 次提交
> 目标：让「新增一个模块」从「看 README 猜惯例」变成「照着目录抄一遍」
> **进度：P0 ✅ → P1 ✅ → P2 待做 → P3 待做**（下面第 2 节是改造前的诊断，保留作对照）

## 0. 一句话诊断

分层是对的（pages / apis / cases / framework 四层分明，这一点比多数同类项目都干净），
但**四层的内部形状不一致**：`cases/` 混用了「按动作拆」和「按模块拆」两套标准，
`pages/` 把同一份表格逻辑复制了三遍，`dashboard_server.py` 一个文件干了四件事。
所以要动的不是架构，是**目录切分标准和重复代码**。

三个关键数字：

| 指标 | 现状 | 影响 |
| --- | --- | --- |
| 单文件最大行数 | 908（dashboard_server.py） | 改一行要读完 900 行 |
| 三个页面对象共有方法 | 38 个 | 改选择器要改 3 处，漏一处就出假通过 |
| 用例里直接写选择器的位置 | 82 处（c_material 44 / c_depot 20 / c_entry 17 / 其他 1） | 前端改版全崩，POM 被架空 |

## 2. 五个结构问题

### 问题 1：`cases/` 存在两套并行的切分标准（最影响可维护性）

实测各文件登记的用例前缀：

| 文件 | 行数 | 用例前缀 | 切分依据 |
| --- | --- | --- | --- |
| c_create / c_edit / c_delete / c_query / c_status / c_entry / c_list | 49~440 | UNIT | 按**动作** |
| c_product | 49 | **UNIT**（不是 MAT） | 名字是模块，内容是 UNIT，错位 |
| c_depot | 769 | DEP | 按**模块** |
| c_material | 861 | MAT | 按**模块** |

同一个 `cases/` 里，新增 UNIT 用例该建 `c_paging.py`，新增 DEP 用例该往 769 行的
`c_depot.py` 里塞——新人无法判断，只能靠读 README。这就是「看着乱」的根源。

**目标**：统一为「模块目录 + 模块内按动作/标签分文件」。模块是唯一一级维度，
因为用例编号（`TC-DEP-xxx`）、菜单（`--module DEP`）、报告分组全都按模块走。

### 问题 2：38 个方法复制了三遍

`unit_page` / `depot_page` / `product_page` 完全同名同义的方法：

```
open  _wait_table_loaded  rows_data  row_count  total_count  pagination_info
empty_text  has_row  count_row  row_index  row_locator  read_row  statuses
search  reset  open_create_modal  open_edit_modal  form_state  click_save
save_success  save_blocked  create  delete  selection  selected_count
header_state  _wait_selected  select_row  select_rows  select_all
clear_selection  click_toolbar  batch_action  set_status  wait_status
wait_row  wait_row_count  cleanup_contains
```

`base_page.py` 只抽了 AntD 的按钮/toast/确认框，**没抽「带表格的列表页」这一层**，
于是这 38 个方法在每个页面对象里各写一遍。总行数 2014 里估计 900+ 行是重复。

**目标**：新增 `pages/table_page.py`（继承 BasePage），承载列表页全部通用能力；
三个业务页面对象只留 `_search_fields`、`_row_parser`、模块特有交互（多单位弹窗、
商品多单位 tab、仓库负责人下拉）。

### 问题 3：用例绕过 POM 直接操作页面

```
cases/c_material.py:44   cases/c_depot.py:20   cases/c_entry.py:17
```

高频裸选择器：`.ant-menu-submenu`（6 次）、`.ant-table`（5 次）、`#unit` / `#standard` / `#color`
这类表单字段 ID（10 次）。这些既不是「业务语义」也不是「稳定契约」，
一旦前端把 `#standard` 改成 `#basicUnitId`，用例和页面对象的中立性同时失效。

**目标**：用例里禁止出现 `locator(` / `wait_for_timeout(` / `goto(`。
真的缺方法就补到页面对象（缺方法本身说明 POM 不完整，是好信号不是坏事）。
可用一条 grep 检查守住：`grep -rn "locator(\|wait_for_timeout" cases/` 应为 0。

### 问题 4：根目录散落 + `dashboard_server.py` 职责过载

908 行里混了四类职责：

- `56~372`：环境探测（python / 浏览器 CDP / 页面 / 站点 / 用例表 / 依赖）+ 健康轮询
- `373~567`：任务执行（RunSession / RunManager，起子进程跑 run_cases）
- `568~907`：HTTP 服务（Handler / 双栈 server / main）
- `612~640`：`prepare_env()` 里去启动 MyTest 浏览器和业务页

同时 `dashboard/index.html` 45KB 里内联了全部 CSS 和 JS。

**目标**：`dashboard/health.py` `dashboard/runner.py` `dashboard/server.py` `dashboard/env.py`，
前端拆 `index.html` + `app.js` + `style.css`。

### 问题 5：工程化缺位

- `管伊佳ERP-测试用例.xlsx`（41KB 二进制）被 git 跟踪。每次 `--update-xlsx` 回填都产生
  一个无法 review 的二进制 diff，而 `*.bak_*.xlsx` 已进忽略列表，说明它确实天天被改。
- `requirements.txt` 只有 4 行、无版本上限、无 lint/format 配置；`tools/allure/node_modules`
  这套 Node 依赖压根没写进任何依赖清单。
- 没有任何 CI、没有 pre-commit、框架自身 1391 行零测试。
- README 701 行承担了全部文档职责（上手、实测发现、页面契约、动作间隔、数据纪律）。

## 5. 关于要不要上 pytest

先给结论：**结构理顺之后再上，且只用 pytest 当 runner，不要重写用例。**

理由：现有 `registry` 有三个 pytest 原生不擅长表达的需求，硬迁会掉能力：

1. **编号即主键**——报告、控制台、Excel 回填都靠 `TC-UNIT-012` 对齐；
2. **同编号双轨实现**（UI + API），靠 `--layer` 切换，pytest 只能靠两套 fixture 绕；
3. **`blocked` 语义**——「环境不具备」要记「阻塞」而不是 skipped，还要写回 Excel。

推荐桥接方案（约 2 小时，收益明显）：

```python
# tests/test_all.py —— 让 pytest 当执行器，registry 当数据源
import pytest, cases
from core import registry
from core.runner import Runner

CASES = registry.all_cases()

@pytest.mark.parametrize("case", CASES, ids=[c.cid for c in CASES])
def test_registry_case(case, ctx):
    result = Runner(ctx, allure=None).run_one(case)
    if result.status == registry.BLOCKED:
        pytest.skip(result.detail)
    assert result.status == registry.PASS, result.detail
```

这样白拿：`pytest -k` / `-x` / `--lf`（只跑上次失败）/ xdist 并行 / 主流 IDE 点绿三角 /
CI 标准 JUnit XML。而 UI 层那套「复用 MyTest 已登录 CDP 会话」的逻辑原样保留在 `ctx` fixture 里,
不用为了 pytest 重写 3695 行用例。
