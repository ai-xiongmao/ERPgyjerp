# 管伊佳ERP 接口契约：多单位 / 商品信息 / 仓库信息

> 采集方式：CDP 挂 Network 监听，在 MyTest 浏览器里真实操作三个页面录制（含新增/编辑/删除/状态/批量/设为默认全链路），
> 再对边界请求做服务端行为探测。采集时间 2026-11-05，原始报文见 `tools/api_dump/`（`dump_*` 只读、`write_*` 写链路）。
>
> 接口自动化代码：`apis/`（封装）+ `cases/<模块>/api.py`（用例）；执行方式见文末。

## 1. 通用约定

| 项 | 值 |
| --- | --- |
| 域名 | `https://cloud.gyjerp.com` |
| 前缀 | `/jshERP-boot` |
| 认证 | 请求头 `x-access-token: <token>`（39 位，前端存 localStorage 的 `pro__Access-Token`） |
| 请求头 | `Content-Type: application/json;charset=UTF-8`、`Accept: application/json` |
| 成功响应 | `{"code":200,"data":{...}}`，写操作多为 `{"message":"成功"}` |
| 失败响应 | **HTTP 仍为 200**，靠 `code` 区分：`301`=数据写入异常、`300`=数据查询异常、`500`=未知异常、`8000005`=业务提示（如条码重复） |
| 错误提示位置 | `data.message`（不是顶层 `message`） |
| 分页 | `currentPage` + `pageSize`，返回 `data.total` + `data.rows` |
| 列表搜索 | `search` 传 **JSON 字符串**（需 URL 编码），不同模块字段不同 |
| 排序 | `column`（如 `createTime`）+ `order`（`desc`/`asc`） |
| 字段裁剪 | `field` 传逗号分隔列名；**不传则返回全字段**，编辑所需的完整对象直接取列表行即可 |

## 2. 接口清单

### 2.1 多单位（`/system/unit`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/unit/list` | 分页列表，`search={"name":"","type":""}` |
| GET | `/unit/getAllList` | 下拉全量，`currentPage=1&pageSize=100` |
| POST | `/unit/add` | 新增 |
| PUT | `/unit/update` | 编辑（需完整对象） |
| POST | `/unit/batchSetStatus` | 启用/禁用（单条与批量同一接口） |
| DELETE | `/unit/delete?id=` | 单条删除 |
| DELETE | `/unit/deleteBatch?ids=1,2,` | 批量删除（**每个 id 后带逗号**） |

新增请求体：
```json
{"basicUnit": "个", "otherUnit": "箱", "ratio": "10"}
```
多副单位时字段后缀递进：`otherUnit/ratio`、`otherUnitTwo/ratioTwo`、`otherUnitThree/ratioThree`。

编辑请求体（前端回传完整对象）：
```json
{"id": 12865, "name": "个/(箱=10个)", "basicUnit": "个", "otherUnit": "箱",
 "otherUnitTwo": null, "otherUnitThree": null, "ratio": "12", "ratioTwo": null,
 "ratioThree": null, "enabled": true, "tenantId": 202005, "deleteFlag": "0"}
```
> `name` 是**服务端按「基本单位/(副单位=比例基本单位)」拼出来的派生字段**，前端回传的是旧值，服务端会重算。

状态请求体：`{"status": false, "ids": "12865,"}`

### 2.2 商品信息（`/material/material`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/material/list` | 分页列表，`search` 含 `materialParam` + 一堆高级查询字段 |
| POST | `/material/add` | 新增（必带 `meList` 条码明细） |
| PUT | `/material/update` | 编辑（完整对象 + `meList`） |
| POST | `/material/batchSetStatus` | 启用/禁用 |
| DELETE | `/material/deleteBatch?ids=1,2,` | 删除 |
| GET | `/material/getMaxBarCode` | 取**当前最大条码**（不是下一个，前端自行 +1） |
| GET | `/material/checkIsExist` | 名称+规格查重，返回 `data.status` |
| GET | `/materialsExtend/checkIsBarCodeExist` | 条码查重，返回 `data.status` |
| GET | `/materialsExtend/getDetailList?materialId=` | 条码明细（编辑时组 `meList` 用） |
| POST | `/material/changeNameToPinYin` | 名称转助记码 |
| GET | `/materialCategory/getMaterialCategoryTree` | 类别树（当前租户为空数组） |
| GET | `/materialAttribute/getNameList` | 多属性名列表 |

列表 `search` 的完整字段（少一个都可能被当成高级查询）：
```json
{"materialParam":"","standard":"","model":"","color":"","brand":"","mfrs":"",
 "otherField1":"","otherField2":"","otherField3":"","weight":"","expiryNum":"",
 "position":"","remark":"","mpList":"扩展1,扩展2,扩展3"}
```

新增请求体：
```json
{"name":"测试商品","unit":"个","mnemonic":"测试商品",
 "meList":[{"id":"17938653455110331975","barCode":"10042027","commodityUnit":"个",
            "sku":"","purchaseDecimal":"","commodityDecimal":"","wholesaleDecimal":"","lowDecimal":""}],
 "stock":[],"sortList":[],"unitId":"","imgName":"","meDeleteIdList":[]}
```
- `meList[].id` 是明细主键，新增时前端用 20 位随机数字；编辑时必须传**库里的真实明细 id**（从 `getDetailList` 取）。
- 编辑时 `stock` 必须是数组（列表行里是数字 0，直接回传会 301）。

### 2.3 仓库信息（`/system/depot`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/depot/list` | 分页列表，`search={"name":"","remark":""}` |
| GET | `/depot/getAllListWithStock?mId=0` | 仓库下拉（带库存） |
| GET | `/depot/checkIsNameExist?name=&id=` | 名称查重，返回 `data.status` |
| POST | `/depot/add` | 新增 |
| PUT | `/depot/update` | 编辑（完整对象） |
| POST | `/depot/batchSetStatus` | 启用/禁用 |
| POST | `/depot/updateIsDefault` | 设为默认，`{"id":38354}` |
| DELETE | `/depot/deleteBatch?ids=1,2,` | 删除 |

新增请求体：`{"name":"仓库A","address":"地址","warehousing":2.5,"truckage":10,"sort":99,"remark":"备注"}`

## 3. 服务端校验实测口径

这是接口层的核心价值：**UI 上的红字/拦截，相当一部分是前端做的，后端并未兜底**。

| 场景 | UI 表现 | 后端实测 | 判定 |
| --- | --- | --- | --- |
| 多单位：只填基本单位 | 提示「副单位不能为空」 | `301 数据写入异常` | 一致（提示不友好） |
| 多单位：**不填基本单位** | 红字「请输入基本单位!」 | **200 成功**，落库 `basicUnit=null`、名称为 `null/(箱=10null)` | **缺陷**：后端无校验 |
| 多单位：只填比例不填副单位 | toast 拦截 | **200 成功** | **缺陷** |
| 多单位：比例=-1 | toast「只能为数字」 | **200 成功** | **缺陷** |
| 多单位：比例=abc | toast 拦截 | `500 未知异常`（不入库） | 拦截生效但返回 500 |
| 多单位：三副单位 | 保存后无数据 | `301 数据写入异常` | **缺陷**：第三副单位不可用 |
| 多单位：四位小数 1.5555 | 提示最多三位 | **200 成功**，落库 1.556（四舍五入） | **偏差** |
| 多单位：比例 0 / 99999999 | 可保存 | 200 成功 | 与用例表记录一致（待产品确认） |
| 多单位：编辑清空基本单位 | 红字拦截 | **200 成功**，名称被写成 `null/(...)`，原数据被破坏 | **缺陷** |
| 多单位：删除被商品引用 | 提示「检测到存在依赖数据，不能删除」 | **200 成功**，商品变悬空引用 | **缺陷**：依赖校验仅在前端 |
| 多单位：名称重复 | 允许 | 200 成功 | 一致（无唯一性） |
| 多单位：查询含 emoji | — | `300 数据查询异常` | **缺陷**：查询条件含 emoji 直接打挂 |
| 商品：空表单/缺名称/缺单位 | 红字必填 | **200 成功**，可建出空名商品 | **缺陷**：后端完全无必填校验 |
| 商品：条码重复 | — | `8000005 商品条码:xxx重复` | 校验正确 |
| 商品：编辑清空名称 | 红字拦截 | 200 成功但静默忽略（数据未变） | **偏差**：前端会误判成功 |
| 商品：查询含 emoji | — | `300 数据查询异常` | **缺陷** |
| 仓库：名称为空 | 红字必填 | `301 数据写入异常` | 一致 |
| 仓库：**名称重复** | 「名称已经存在」 | **200 成功** | **缺陷**：唯一性只靠前端 `checkIsNameExist` |
| 仓库：名称超长/emoji | 提示 | `301 数据写入异常` | 拦截生效 |
| 仓库：仓储费 abc | 不入库 | `500 未知异常`（不入库） | 一致（无友好提示） |
| 仓库：编辑清空名称 | 红字拦截 | 200 成功但静默忽略 | **偏差** |
| 仓库：设为默认不存在的 id | — | **200 成功** | **缺陷**：无存在性校验 |
| 仓库：批量状态空 ids | — | `500 未知异常` | 参数校验缺失 |
| 三页：查询含 emoji | — | `300 数据查询异常` | **缺陷**（三页通病） |

## 4. 接口自动化落地

```
apis/                    接口封装（对标 pages/）
  unit_api.py            多单位：list/all/find/add_ok/update_ok/set_status/delete_batch/options
  material_api.py        商品：含 meList 组装、条码取号与查重、明细回查
  depot_api.py           仓库：含 set_default/check_name_exist
framework/
  api_client.py          HTTP 客户端：token 获取与缓存、统一断言 ok()/reject()
  api_context.py         接口执行上下文：造数据记账、按 id 精确回收
cases/unit/api.py        多单位接口用例
cases/material/api.py    商品接口用例
cases/depot/api.py       仓库接口用例
tools/
  api_recorder.py        只读抓包（页面加载/查询/翻页/开关弹窗）
  api_recorder_write.py  写接口抓包（测试前缀下跑完整 CRUD）
  api_probe_server.py    服务端校验行为探测
```

执行：

```bash
# 接口层全量（执行计划 78 条 = 71 条有实现 + 7 条阻塞标注，约 3 分钟）
./.venv/Scripts/python.exe run_cases.py run --layer api

# 按模块 / 编号
./.venv/Scripts/python.exe run_cases.py run --layer api --module UNIT MAT
./.venv/Scripts/python.exe run_cases.py run --layer api --only TC-DEP-017,TC-DEP-025

# UI 层（默认，行为不变）
./.venv/Scripts/python.exe run_cases.py run

# 看接口层覆盖了哪些
./.venv/Scripts/python.exe run_cases.py list --layer api
```

- token 首次从 MyTest 浏览器取并缓存到 `.api_token`，之后浏览器不开也能跑（失效会自动回源）；
- 也可以不走命令行：`run_cases.py` 不带参数进菜单，选 `5 接口层执行`，子菜单支持 全部 / 按模块 / 按编号 / 只看清单；
- 接口层造数据同样遵守「测试前缀 + 跑完回收」，回收用 **id 精确删**（因为用例可能把名称改坏，按名字搜不到）；
- 「本应被拦截却成功了」的用例会**先回滚脏数据再判失败**，不会污染后续用例。
